# 機能仕様

## 目的

回転する3D地球儀から、世界主要都市の気温・湿度・天気・現地日時を見渡せる、静的なGitHub Pagesアプリ。

## Phase 1：地球儀（実装済み）

- ドラッグ／タッチスワイプによる左右回転とホイール／ピンチでのズーム。
- リセット、自動回転、WebGLが使えない場合のエラー表示。
- 地表画像・大気の光・星空・レスポンシブUI。

## Phase 2：都市と天気（実装済み）

- 20都市の座標とIANAタイムゾーンを `src/lib/cities.ts` で一元管理（追加都市：Bangkok、Moscow、Brasília、Manila）。
- Open-MeteoのForecast APIへ緯度経度を配列で渡し、`current=temperature_2m,relative_humidity_2m,weather_code,is_day,apparent_temperature,wind_speed_10m,wind_direction_10m,precipitation,cloud_cover`を取得する。
- 同じAPIリクエストで `hourly=precipitation_probability` を取得。各都市の `current.time` と同一UTC時間帯の1時間予報を選び、値がない場合は `null` にする。
- 体感温度（°C）、風速（km/h）、風向（北・北東等）、降水量（mm）、雲量（%）、降水確率（%）は選択都市の詳細欄にのみ表示。
- リクエスト時の`timezone=GMT`で観測時刻をUTCとして解釈。
- 20分間有効なセッションキャッシュ、30分ごとの再取得、タブ復帰時の更新と手動更新。
- 気象データ構造の変更に伴いキャッシュのバージョンを2へ更新し、旧キャッシュの表示を防止。
- 天気の取得失敗時はエラーを表示。取得済みデータは保持し、架空の気象値で埋めない。
- 追加気象値は個別に数値・範囲を検証し、欠損しても基本データは表示する。0と欠損を区別する。
- 地球儀の回転とズームに合わせて20都市すべての座標を投影。地球の裏側や地平線の向こうにある都市マーカーを隠す。
- 経度と `SphereGeometry` のUVを一致させる：本初期姿勢では経度0°＝+X、東経90°＝-Z、西経90°＝+Z。都市マーカーと太陽方向で共通変換を使い、回帰テストで照合。
- 地球儀上は円形マーカーだけを表示し、引き出し線・四角い都市カード・天気テキストは表示しない。
- 表側の全都市マーカーを描画し、画面幅による表示数上限は設けない。裏側のマーカーは地球の回転に応じて現れる。
- マーカーは通常青緑色、選択中の都市だけオレンジ色。都市マーカーをクリック・タップするとプルダウンの選択と詳細パネルが更新される。
- プルダウンから選択しても、対応する都市マーカーの色が変わる。
- 都市選択時には、その経度が画面中央へ向くようカメラを最短回転で約2.1秒かけて移動する。
- 上下回転禁止の従来操作を維持するため、都市の緯度方向にはカメラを傾けない。
- 都市選択で自動回転を止め、ドラッグ・スワイプ・ホイール・ピンチなどの手動操作で移動を中断する。
- 動きを減らすOS設定では、アニメーションせずに直ちに対象都市の経度へ移動する。

## Phase 3：現地時刻と昼夜（実装済み）

- `Intl.DateTimeFormat`とIANAタイムゾーンを使い、夏時間を考慮した現地日時を表示。
- UTC日時・季節から太陽赤緯、均時差、太陽直下点の概算を求める。
- 地球の各面の法線と太陽方向の内積で昼夜の明暗を切り替えるShaderを採用。
- 夜側は夜景テクスチャを表示。時間は1分ごとに更新する。
- 天気APIの昼夜判定は各都市の詳細欄に表示し、全球の昼夜は天文計算と独立させる。

## データ更新と限界

- データ取得は全訪問者のブラウザで発生する。セッションキャッシュと間隔で削減しているが、利用者増加時はGitHub Actionsでの定期取得＋静的JSON配布への切替を検討する。
- 使用条件はOpen-Meteoの非商用利用規約に従う。商用運用時には別契約が必要な場合がある。
- 現在値は数値予報モデルからの推定であり、都市の公式な観測値を保証しない。
- 太陽位置の計算は視覚的な概算であり、天文観測・航法目的に使わない。
- 全20都市にマーカーを配置するが、裏側の都市は地球に隠れるため同時には見えない。

## 非機能要件

- GitHub Pagesの静的配信。サーバー・APIキー不要。
- スマートフォンのスワイプ・ピンチに対応、GPU負荷を抑えるためピクセル比は最大2。
- API不調、画像取得失敗、WebGL非対応で壊れないようフォールバックを設ける。
- READMEと仕様は画面・API仕様を変更した際に更新する。
